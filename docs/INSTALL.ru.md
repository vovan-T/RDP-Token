# Установка RDP-Token на Linux

Это предварительная лабораторная версия. Сначала прочитай [SECURITY.md](../SECURITY.md).
Не устанавливай поверх действующего шлюза без резервной копии.

## 1. Подготовить каталог

Распакуй архив с исходниками в отдельный каталог, например `/opt/RDP-Token`.
Выполняй дальнейшие команды из него. Нужны уже установленные Docker Engine,
Docker Compose и OpenSSL. Установка пакетов в инструкции автоматически не выполняется.
Compose использует сеть Linux-хоста; Docker Desktop не является проверенной целью.

```sh
cd /opt/RDP-Token
sh scripts/create-env.sh
vim .env
```

В `.env` укажи:

- `RDP_TOKEN_PUBLIC_RDP_HOST`: адрес, к которому RDP-клиент реально подключается.
  Можно DNS-имя или IP, без `https://` и без порта.
- `RDP_TOKEN_SERVER_CERT`, `RDP_TOKEN_SERVER_KEY`: абсолютные пути к серверной
  цепочке PEM и закрытому TLS-ключу. Имя сайта должно быть в SAN сертификата.
- `RDP_TOKEN_BOOTSTRAP_ADMIN_SERIAL`: серийный номер сертификата администратора
  в HEX без двоеточий. Это не серийный номер USB-токена.
- `RDP_TOKEN_HTTPS_PORT`: порт HTTPS, по умолчанию 18443.
- `RDP_TOKEN_CLAIM_SECONDS`: 50 секунд на подключение и повторные попытки.
- `RDP_TOKEN_PORT_MIN/MAX`: диапазон выделяемых портов, по умолчанию 60000–60999.
  После первой инициализации диапазон хранится в SQLite и редактируется в панели.

`scripts/create-env.sh` создаёт случайный секрет и не перезаписывает существующий
файл. Не оставляй `CHANGE_ME` и `example.invalid` в рабочей конфигурации.

## 2. Доверие и права

```sh
sudo sh scripts/prepare-data.sh
```

Помести публичный сертификат клиентского CA в `certs/client-ca.pem`, а актуальный
CRL этого CA — в `certs/client.crl.pem`. Сделай оба файла доступными на чтение UID
10001 (обычно режим 0644). Закрытый ключ CA на шлюз не копируется.
HTTPS-сертификат должен быть доверенным на клиентах. Для первого теста используй
клиентские сертификаты, выпущенные напрямую выделенным тестовым корневым CA.

## 3. Запуск

```sh
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail 50 app nginx
```

Если работаешь не под root, файлы `.env` и исходники должны быть доступны твоему
пользователю; каталог `data` предназначен для контейнерного UID/GID 10001.
Не делай каталог базы общедоступным ради обхода ошибки прав.

Портал: `https://<имя-из-сертификата>:18443/`. При необходимости настрой прямое
TCP-перенаправление 443 → 18443. Для RDP перенаправляй только назначенные порты на
такие же порты шлюза. Изолируй их firewall: первый TCP-клиент может забрать чужое
открытое разрешение. Не открывай весь диапазон без необходимости.

Не ставь перед порталом обычный TLS-терминирующий HTTP-прокси: он изменит путь
проверки клиентского сертификата. Backend 18081 наружу не открывается.

## 4. Первый вход и системы

Вставь токен с сертификатом администратора на клиенте, открой портал и выбери
этот сертификат. После проверки цепочки и CRL его serial из `.env` будет добавлен
как ADMIN. В панели добавь системы: название, внутренний IP и порт RDP (обычно
3389). Шлюз должен иметь сетевой доступ к этим адресам.

Добавь сертификаты пользователей и назначь им системы. Для пользователя доступ
к панели управления отсутствует. При разрешении доступа начинается окно 50 секунд.
Скачай RDP-файл и открой его. Вход в конечную Windows выполняется её учётными данными.

Буфер обмена включён. Смарт-карты внутрь RDP не передаются. Пароль сохраняется
штатным клиентом Windows, если политики разрешают; шлюз его не хранит.

## 5. Аварийный вход

```sh
sudo docker exec rdp-token-app recovery
```

Команда печатает одноразовый код, действительный 30 минут. Введи его в окне
«Аварийный вход» настольного клиента. Полученная административная сессия также
ограничена 30 минутами. Новый код отменяет предыдущие неиспользованные коды и
аварийные сессии. Не присылай код в публичные сообщения.

## 6. Обновление и резервная копия

Перед заменой исходников останови app в согласованное время и сделай защищённую
копию `.env`, `data/` и `certs/`. Не копируй активную SQLite-базу обычным `cp` без
остановки или штатного SQLite backup. TLS-ключ также нужен для восстановления,
хранить его следует отдельно и защищённо.

```sh
sudo docker compose stop app
# Сделай резервную копию и замени исходники, не трогая .env/data/certs.
sudo docker compose up -d --build --no-deps app
```

Остановка/перезапуск шлюза прерывает текущие RDP-соединения. Изменения параметров
генератора RDP не меняют ранее скачанные файлы — скачай их заново.

## Что проверять

- Прямой HTTP-запрос без nginx-заголовков к 127.0.0.1:18081 должен получить отказ.
- Без доверенного клиентского сертификата портал не даёт доступ.
- Просроченный/отозванный сертификат и неактуальный CRL должны приводить к отказу.
- Веб-счётчик показывает 50; установленное соединение работает после его истечения.
- После разрыва повтор возможен только в остаток исходного окна с того же IP.
- Windows может блокировать сохранённые пароли своей политикой.

Официальные ориентиры: [Docker Compose](https://docs.docker.com/compose/),
[nginx TLS](https://nginx.org/en/docs/http/ngx_http_ssl_module.html).
